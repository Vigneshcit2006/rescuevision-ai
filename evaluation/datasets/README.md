# Evaluation datasets

There is no real-world video dataset in this project. All evaluation in
`evaluation/` runs against `backend/app/vision/video_source.py::SyntheticFrameSource`,
a deterministic, programmatically-rendered frame generator. This document
exists so it is unambiguous, when reading `evaluation/results/*.json` and
`evaluation/reports/evaluation_report.md`, exactly what data produced those
numbers.

## What the "dataset" actually is

`SyntheticFrameSource(scenario, num_frames, fps)` draws simple shapes
(rectangles, circles) with `cv2` primitives onto a plain 640x480 BGR canvas,
frame by frame, plus small per-frame pseudo-random noise seeded by the frame
index (`np.random.default_rng(seed=i)`). There is no photographic, video, or
otherwise externally-sourced footage anywhere in this repository's test path.
Consequences:

- **No copyright/licensing concerns** -- every pixel is generated by drawing
  code in this repo, not sourced from any external clip, dataset, or camera.
- **Fully reproducible** -- for a given `(scenario, num_frames, fps)` the frame
  sequence is bit-for-bit deterministic across machines and runs (no random
  seed varies between runs; the only randomness is the per-frame noise, which
  is itself seeded by the frame index).
- **Small and synthetic, not a benchmark corpus** -- there are exactly four
  scenario names, i.e. n=4 "clips" total, each a single procedurally generated
  sequence rather than an independent sample of real-world variation.

## The four scenarios

| Scenario | Ground truth | What is rendered |
|---|---|---|
| `normal` | Never reaches `possible` or `confirmed` | A static piece of furniture; no incident signal is ever introduced. |
| `fire_smoke` | Should reach `confirmed` | An orange/red "flame" circle that grows from frame ~30, plus a grey "smoke" plume rising from frame ~50. |
| `person_down` | Should reach `confirmed` | A standing rectangle silhouette that widens/flattens between frames ~40-55 to simulate a fall, then stays horizontal. |
| `route_obstruction` | Should reach `confirmed` | A high-contrast vehicle-like rectangle that grows across a marked "restricted route" region from frame ~25. |

## Why this is the only data available, and what that means for the results

This project has no camera feed, no recorded incident footage, and no
licensed or public disaster-response video dataset wired into it. Building or
sourcing one was out of scope for this evaluation pass. Every accuracy/recall/
F1 figure in `evaluation/reports/evaluation_report.md` is therefore an
**illustrative check of the pipeline's internal logic on n=4 synthetic clips**,
not a claim about real-world detection accuracy. See that report's
"Limitations of this evaluation" section for the full caveat.

## Reproducing the exact frames used

```python
import sys
sys.path.insert(0, "backend")
from app.vision.video_source import SyntheticFrameSource

src = SyntheticFrameSource("fire_smoke", num_frames=260, fps=15.0)
frames = list(src.frames())  # deterministic; same sequence every run
```

`evaluation/scripts/run_evaluation.py` uses `num_frames=260` for the
detection-quality measurements (empirically confirmed to give every incident
scenario enough time to reach `confirmed`; see
`backend/tests/test_vision_pipeline.py`, which uses the same frame count) and
`num_frames=200` for the raw per-frame performance timings.
